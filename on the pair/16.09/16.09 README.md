# Лабораторная работа. Оконные функции в MS SQL Server

Анализ использования оконных функций (`DENSE_RANK`, `OVER`) и сортировки

## Слайд 4. Простой SELECT с NULL AS rank

### Что требовалось
Вывести список преподавателей с сортировкой по имени (убывание) и по коду (`TEACHER`).

### Что сделано

    USE College;
    GO

    SELECT
        NULL          AS rank,
        TEACHER_NAME  AS name,
        PULPIT        AS department
    FROM TEACHER
    ORDER BY TEACHER_NAME DESC, TEACHER;

### Результат

| rank | name | department |
|---|---|---|
| NULL | Фёдоров Сергей Николаевич | K_MGT |
| NULL | Соколов Артём Игоревич | K_LAW |
| NULL | Смирнов Алексей Владимирович | K_MAT |
| NULL | Сидорова Анна Сергеевна | K_PI |
| NULL | Петров Пётр Петрович | K_IVT |
| NULL | Новикова Елена Павловна | K_ECO |
| NULL | Морозов Дмитрий Андреевич | K_PHY |
| NULL | Кузнецова Мария Ивановна | K_PI |
| NULL | Иванов Иван Иванович | K_IVT |
| NULL | Волкова Ольга Дмитриевна | K_MAT |
| NULL | English John | K_LIN |

### Анализ
- `NULL AS rank` — заглушка для будущей колонки с рангом.
- `ORDER BY TEACHER_NAME DESC` — сортировка по имени **убывание**.
- Второй ключ `TEACHER` — для стабильности сортировки при одинаковых именах.

### Вывод
Базовый SELECT без вычислений. Колонка `rank` пока не заполнена — в следующих слайдах в неё встанет результат `DENSE_RANK()`.

## Слайд 6. DENSE_RANK() как rank (одна строка)

### Что требовалось
Добавить колонку с рангом через оконную функцию `DENSE_RANK()`.

### Что сделано

    SELECT
        DENSE_RANK() OVER (ORDER BY TEACHER_NAME DESC) AS rank,
        TEACHER_NAME  AS name,
        PULPIT        AS department
    FROM TEACHER
    ORDER BY rank, TEACHER;

### Результат

| rank | name | department |
|---|---|---|
| 1 | Фёдоров Сергей Николаевич | K_MGT |
| 2 | Соколов Артём Игоревич | K_LAW |
| 3 | Смирнов Алексей Владимирович | K_MAT |
| 4 | Сидорова Анна Сергеевна | K_PI |
| 5 | Петров Пётр Петрович | K_IVT |
| 6 | Новикова Елена Павловна | K_ECO |
| 7 | Морозов Дмитрий Андреевич | K_PHY |
| 8 | Кузнецова Мария Ивановна | K_PI |
| 9 | Иванов Иван Иванович | K_IVT |
| 10 | Волкова Ольга Дмитриевна | K_MAT |
| 11 | English John | K_LIN |

### Анализ
- **`DENSE_RANK()`** — присваивает ранги **без пропусков**.
- `OVER (ORDER BY TEACHER_NAME DESC)` — окно: сортировка по имени.
- `ORDER BY rank, TEACHER` — сортировка результата.

**Отличие `DENSE_RANK` от `RANK`:** при одинаковых значениях `RANK` делает **пропуски** (1, 2, 2, 4), а `DENSE_RANK` — **нет** (1, 2, 2, 3).

### Вывод
`DENSE_RANK()` — оконная функция, которая нумерует строки **без пропусков**. Удобна, когда важно «сколько уникальных значений», а не «позиция в рейтинге».

## Слайд 8. DENSE_RANK() как rank (многострочное окно)

### Что требовалось
Показать **многострочное** оформление `OVER(...)` — разнесение `ORDER BY` внутри окна на несколько строк.

### Что сделано

    SELECT
        DENSE_RANK() OVER (
            ORDER BY TEACHER_NAME DESC
        ) AS rank,
        TEACHER_NAME  AS name,
        PULPIT        AS department
    FROM TEACHER
    ORDER BY rank, TEACHER;

### Результат

Тот же, что и на слайде 6 — 11 строк с рангами 1–11.

### Анализ
- Синтаксически **ничего не поменялось** — результат идентичен слайду 6.
- Многострочная запись **улучшает читаемость** для сложных окон.
- Для нескольких окон (`OVER w1`, `OVER w2`) — нагляднее.

### Вывод
Стиль оформления **не влияет** на результат. Многострочная запись рекомендуется, когда в `OVER` больше одного параметра (например, `PARTITION BY` + `ORDER BY` + `ROWS`).

## Слайд 9. Два окна: r_asc и r_desc

### Что требовалось
Показать **два окна в одном запросе**: `DENSE_RANK` в прямом и обратном порядке.

### Что сделано

    SELECT
        DENSE_RANK() OVER (
            ORDER BY TEACHER_NAME ASC
        ) AS r_asc,
        DENSE_RANK() OVER (
            ORDER BY TEACHER_NAME DESC
        ) AS r_desc,
        TEACHER_NAME  AS name,
        PULPIT        AS department
    FROM TEACHER
    ORDER BY TEACHER_NAME, TEACHER;

### Результат

| r_asc | r_desc | name | department |
|---|---|---|---|
| 1 | 11 | English John | K_LIN |
| 2 | 10 | Волкова Ольга Дмитриевна | K_MAT |
| 3 | 9 | Иванов Иван Иванович | K_IVT |
| 4 | 8 | Кузнецова Мария Ивановна | K_PI |
| 5 | 7 | Морозов Дмитрий Андреевич | K_PHY |
| 6 | 6 | Новикова Елена Павловна | K_ECO |
| 7 | 5 | Петров Пётр Петрович | K_IVT |
| 8 | 4 | Сидорова Анна Сергеевна | K_PI |
| 9 | 3 | Смирнов Алексей Владимирович | K_MAT |
| 10 | 2 | Соколов Артём Игоревич | K_LAW |
| 11 | 1 | Фёдоров Сергей Николаевич | K_MGT |

### Анализ
- **Два независимых окна** — каждое со своим `ORDER BY`.
- `r_asc` — ранг в прямом порядке (А→Я).
- `r_desc` — ранг в обратном порядке (Я→А).
- **Сумма `r_asc + r_desc` всегда = 12** (11 + 1).
- **SQL Server НЕ поддерживает** синтаксис `WINDOW w1 AS (...)` (это MySQL/ClickHouse).

### Вывод
Можно использовать **несколько окон** в одном запросе. Каждое окно описывается **внутри своего `OVER(...)`**. Это ключевое отличие SQL Server от MySQL/ClickHouse, где окно выносится в раздел `WINDOW`.

## Слайд 12. Сортировка по кафедре + имя убывание

### Что требовалось
Вывести преподавателей с сортировкой **по кафедре (возрастание)** и **по имени (убывание)**.

### Что сделано

    SELECT
        NULL          AS rank,
        TEACHER_NAME  AS name,
        PULPIT        AS department,
        GENDER        AS salary
    FROM TEACHER
    ORDER BY PULPIT, TEACHER_NAME DESC, TEACHER;

### Результат

| rank | name | department | salary |
|---|---|---|---|
| NULL | Новикова Елена Павловна | K_ECO | Ж |
| NULL | Петров Пётр Петрович | K_IVT | М |
| NULL | Иванов Иван Иванович | K_IVT | М |
| NULL | Соколов Артём Игоревич | K_LAW | М |
| NULL | English John | K_LIN | М |
| NULL | Смирнов Алексей Владимирович | K_MAT | М |
| NULL | Волкова Ольга Дмитриевна | K_MAT | Ж |
| NULL | Фёдоров Сергей Николаевич | K_MGT | М |
| NULL | Морозов Дмитрий Андреевич | K_PHY | М |
| NULL | Сидорова Анна Сергеевна | K_PI | Ж |
| NULL | Кузнецова Мария Ивановна | K_PI | Ж |

### Анализ
- **Первый ключ** — `PULPIT` (по возрастанию).
- **Второй ключ** — `TEACHER_NAME DESC` (по убыванию).
- **Третий ключ** — `TEACHER` (стабильность).
- `GENDER AS salary` — переименование для аналогии с презентацией.

### Вывод
`ORDER BY` поддерживает **несколько ключей** с разными направлениями. Порядок ключей **важен** — сортировка идёт **слева направо**. Если первый ключ уникален — остальные не влияют.

## Общий вывод по блоку

| Слайд | Что показал |
|---|---|
| 4 | Простой SELECT + сортировка |
| 6 | `DENSE_RANK() OVER (ORDER BY ...)` |
| 8 | Многострочное оформление `OVER(...)` |
| 9 | Два окна в одном запросе |
| 12 | Многоуровневая сортировка |

**Ключевые принципы:**
1. **Оконные функции** (`DENSE_RANK`, `ROW_NUMBER`, `RANK`) работают **поверх** результата, не сворачивая строки.
2. **`OVER(...)`** описывает окно: `PARTITION BY`, `ORDER BY`, `ROWS`.
3. **SQL Server** не поддерживает `WINDOW w AS (...)` — окно пишется **внутри** `OVER`.
4. **`DENSE_RANK` без пропусков**, `RANK` — с пропусками.
5. **`ORDER BY`** — несколько ключей, разные направления, порядок слева направо.
