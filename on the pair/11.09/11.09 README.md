## Слайд 14. Переменные и IF/ELSE

### Что требовалось
Продемонстрировать использование переменных (`DECLARE`, `SET`, `SELECT @var = …`) и конструкции `IF / ELSE IF / ELSE`.

### Что сделано

    DECLARE @y1 INT, @y2 NUMERIC(8,3), @y3 NUMERIC(8,3), @y4 NUMERIC(8,3);

    SET @y1 = (SELECT SUM(AUDITORIUM_CAPACITY) FROM AUDITORIUM);

    IF @y1 > 150
    BEGIN
        PRINT 'общее количество мест больше 150';
        SELECT @y2 = CAST((SELECT COUNT(*) FROM AUDITORIUM) AS NUMERIC(8,3));
        SELECT @y3 = (SELECT CAST(AVG(AUDITORIUM_CAPACITY) AS NUMERIC(8,3)));
        SET @y4 = (SELECT CAST(COUNT(*) AS NUMERIC(8,3)) FROM PROGRESS);
        SELECT @y1 AS '@y1', @y2 AS '@y2', @y3 AS '@y3', @y4 AS '@y4';
    END
    ELSE IF @y1 > 100
        PRINT 'общее количество мест от 100 до 150';
    ELSE IF @y1 > 50
        PRINT 'общее количество мест от 50 до 100';
    ELSE
        PRINT 'общее количество мест меньше 50';

### Результат

| @y1 | @y2 | @y3 | @y4 |
|---|---|---|---|
| 648.000 | 10.000 | 64.000 | 3.000 |

### Анализ
- `SUM(AUDITORIUM_CAPACITY) = 648` — общее количество мест.
- Условие `@y1 > 150` истинно → выполнилась **первая** ветка `IF`.
- `BEGIN…END` группирует **4 оператора** в один блок.
- `PRINT` выводит сообщение, `SELECT` — таблицу со значениями переменных.

### Вывод
Условия проверяются **сверху вниз** — при первом истинном остальные пропускаются. `BEGIN…END` нужен, если в ветке **больше одного** оператора.

## Слайд 28. Переменные + группировка + JOIN

### Что требовалось
Показать использование переменных для итоговых показателей + `GROUP BY` + `PRINT`.

### Что сделано

    USE college;
    GO

    DECLARE
        @StudentsCount INT = (SELECT COUNT(*) FROM STUDENT),
        @AuditoriumCount INT = (SELECT COUNT(*) FROM AUDITORIUM),
        @TeacherCount INT = (SELECT COUNT(*) FROM TEACHER);

    SELECT AUDITORIUM_TYPE AS [Тип аудитории], COUNT(*) AS [Количество]
    FROM AUDITORIUM GROUP BY AUDITORIUM_TYPE;

    SELECT PULPIT AS [Кафедра], COUNT(*) AS [Количество]
    FROM SUBJECT GROUP BY PULPIT;

    PRINT 'Количество студентов  : ' + CAST(@StudentsCount AS VARCHAR(10));
    PRINT 'Количество аудиторий  : ' + CAST(@AuditoriumCount AS VARCHAR(10));
    PRINT 'Количество преподавателей : ' + CAST(@TeacherCount AS VARCHAR(10));

### Результат

| Тип аудитории | Количество аудиторий |
|---|---|
| COMP | 2 |
| LAB | 2 |
| LECT | 2 |
| PRAC | 2 |
| SEM | 1 |
| SPORT | 1 |

| Кафедра | Количество дисциплин |
|---|---|
| K_ECO | 1 |
| K_IVT | 2 |
| … | … |

### Анализ
- Переменные объявляются **с инициализацией** через `= (SELECT COUNT(*))`.
- `GROUP BY` считает количество по категориям.
- `PRINT` выводит итоговые значения.
- **Важно:** `@StudentsCount` — `INT`, при конкатенации нужен `CAST(... AS VARCHAR)`.

### Вывод
Комбинация агрегатов, группировки и переменных даёт **сводный отчёт**. Переменные удобны для повторного использования одних и тех же значений.

## Слайд 31. Создание кластеризованного индекса и `sp_help`

### Что требовалось
Создать кластерный индекс на heap-таблице и посмотреть структуру через `sp_help`.

### Что сделано

    USE College;
    GO

    CREATE CLUSTERED INDEX IX_Products_ProductID ON dbo.Products (ProductID);
    GO

    EXEC sp_help TEACHER;
    GO

### Результат `sp_help TEACHER`

| Column_name | Type | Length | Nullable |
|---|---|---|---|
| TEACHER | char | 10 | no |
| TEACHER_NAME | char | 50 | yes |
| GENDER | char | 1 | yes |
| PULPIT | char | 20 | yes |

| constraint_type | constraint_name |
|---|---|
| PRIMARY KEY (clustered) | PK_TEACHER |

### Анализ
- `CREATE CLUSTERED INDEX` создаёт **физический порядок** строк.
- `sp_help` возвращает **несколько наборов**:
  - структура колонок,
  - индексы,
  - ограничения (PK, FK),
  - зависимости.

### Вывод
`sp_help` — удобная системная процедура для **быстрого обзора** объекта: колонки, типы, ограничения, индексы.

## Слайд 54. Дополнение таблицы колонкой BDATE

### Что требовалось
Добавить колонку `BDATE` в таблицу `TEACHER` со значением по умолчанию.

### Что сделано

    ALTER TABLE TEACHER
    ADD BDATE DATE NOT NULL
        CONSTRAINT DF_TEACHER_BDATE DEFAULT '19600101';
    GO

    SELECT * FROM TEACHER ORDER BY TEACHER;

### Результат
Все преподаватели получили `BDATE = 1960-01-01`.

### Анализ
- `ALTER TABLE ADD` добавляет **новую колонку**.
- `NOT NULL` + `DEFAULT` — обязательное значение для **существующих** строк.
- **Именованный** constraint (`DF_TEACHER_BDATE`) удобнее удалять, чем анонимный.

### Вывод
Добавление колонки с `DEFAULT` автоматически заполняет существующие строки. Именованные constraints — стандарт для поддерживаемых баз.

## Слайд 29. Области видимости переменных

### Что требовалось
Показать разницу между переменными **уровня пакета** и **уровня блока** `BEGIN…END`.

### Что сделано

    PRINT 'пакет1: начало----------------';
    DECLARE @x0 INT = 0;
    PRINT 'пакет1:@x0 = ' + CAST(@x0 AS CHAR(1));

    BEGIN
        DECLARE @x1 INT = 1;
        PRINT '  блок1: начало ------------';
        PRINT '  блок1:@x0 = ' + CAST(@x0 AS CHAR(1));
        PRINT '  блок1:@x1 = ' + CAST(@x1 AS CHAR(1));

        BEGIN
            DECLARE @x2 INT = 2;
            PRINT '    блок2:@x0 = ' + CAST(@x0 AS CHAR(1));
            PRINT '    блок2:@x1 = ' + CAST(@x1 AS CHAR(1));
            PRINT '    блок2:@x2 = ' + CAST(@x2 AS CHAR(1));
        END;

        BEGIN
            PRINT '    блок3:@x0 = ' + CAST(@x0 AS CHAR(1));
            PRINT '    блок3:@x1 = ' + CAST(@x1 AS CHAR(1));
        END;
    END;

    PRINT 'пакет1: конец-----------------';
    GO

### Результат

    пакет1: начало----------------
    пакет1:@x0 = 0
      блок1: начало ------------
      блок1:@x0 = 0
      блок1:@x1 = 1
        блок2:@x0 = 0
        блок2:@x1 = 1
        блок2:@x2 = 2
        блок3:@x0 = 0
        блок3:@x1 = 1
    пакет1: конец-----------------

### Анализ

| Переменная | Уровень | Где видна |
|---|---|---|
| @x0 | пакет | везде |
| @x1 | блок 1 | блок 1 и вложенные |
| @x2 | блок 2 | только блок 2 |

**`@x2` не видна в блоке 3** — она объявлена в **другом** блоке. SQL Server вернёт ошибку `Must declare the scalar variable "@x2"`.

### Вывод
Переменные живут **внутри блока**, где объявлены. `GO` — разделитель **пакетов**: всё, что объявлено до `GO`, не видно после `GO`.

## Слайд 30. Проверка наличия строк и суммы мест

### Что требовалось
Показать `IF EXISTS` и `IF (SELECT SUM(...))`.

### Что сделано

    USE College;
    GO

    -- Блок 1: проверка наличия строк в PULPIT
    IF EXISTS (SELECT * FROM PULPIT)
        PRINT 'в таблице PULPIT есть строки';
    ELSE
        PRINT 'в таблице PULPIT нет строк';

    -- Блок 2: проверка суммы мест в AUDITORIUM
    IF (SELECT SUM(AUDITORIUM_CAPACITY) FROM AUDITORIUM) > 200
        PRINT 'общее количество мест больше 200';
    ELSE
        PRINT 'общее количество мест меньше 200';

### Результат

    в таблице PULPIT есть строки
    общее количество мест больше 200

### Анализ
- **`IF EXISTS (SELECT * FROM …)`** — стандартная проверка «есть ли строки». SQL Server останавливается на первой найденной — **быстро**.
- **`IF (SELECT SUM(...)) > 200`** — скалярный подзапрос возвращает **одно** число.
- Если бы в `AUDITORIUM` не было строк, `SUM` вернул бы `NULL`, и условие ушло бы в `ELSE`.

### Вывод
`IF EXISTS` — эффективная проверка наличия данных. `IF (SELECT …)` — для сравнения агрегатов. Оба варианта короче и читабельнее, чем `IF @@ROWCOUNT`.

## Слайд 31 (второй). Простое IF/ELSE с @x1

### Что требовалось
Самый простой пример `IF/ELSE IF/ELSE` с одной переменной.

### Что сделано

    USE College;
    GO

    DECLARE @x1 INT = 0;
    SET @x1 = (SELECT SUM(AUDITORIUM_CAPACITY) FROM AUDITORIUM);

    IF @x1 > 200
        PRINT 'общее количество мест больше 200';
    ELSE IF @x1 > 100
        PRINT 'общее количество мест от 100 до 200';
    ELSE IF @x1 > 50
        PRINT 'общее количество мест от 50 до 100';
    ELSE
        PRINT 'общее количество мест меньше 50';

### Результат

    общее количество мест больше 200

### Анализ
- `SUM = 648 > 200` → сработала **первая** ветка.
- `ELSE IF` — это `ELSE` + вложенный `IF`. Синтаксически пишется слитно.
- Как только условие истинно — **остальные не проверяются**.

### Вывод
Классический пример **многоуровневого условия**. Порядок ветвей **важен**: от более строгого к менее строгому.
