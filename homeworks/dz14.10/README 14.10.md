## Слайд 13. Создание SQL-логина с отключённой политикой паролей

### Что требовалось
Показать, что при CHECK_POLICY = OFF SQL Server разрешает создание логина со слабым паролем.

### Что сделано

CREATE LOGIN dev1
WITH PASSWORD = '12',
     DEFAULT_DATABASE = college,
     DEFAULT_LANGUAGE = [us_english],
     CHECK_EXPIRATION = OFF,
     CHECK_POLICY = OFF;

Результат: Выполнение команд успешно завершено.

### Разбор параметров

| Параметр | Значение | Что означает |
|---|---|---|
| PASSWORD | '12' | Пароль 2 символа (слабый) |
| DEFAULT_DATABASE | college | База по умолчанию |
| DEFAULT_LANGUAGE | us_english | Язык сессии |
| CHECK_EXPIRATION | OFF | Пароль не истекает |
| CHECK_POLICY | OFF | Политика Windows НЕ проверяется |

### Анализ
Пароль '12' нарушает политику Windows: длина < 8, нет заглавных, нет спецсимволов. При CHECK_POLICY = ON SQL Server отклонил бы создание с ошибкой Msg 15116. Но CHECK_POLICY = OFF отключает проверку.

### Вывод
CHECK_POLICY = OFF — опасная настройка. В продакшене использовать только CHECK_POLICY = ON.

## Слайд 14. Создание логина Windows

### Что требовалось
Создать логин для Windows-учётной записи.

### Что сделано

CREATE LOGIN [Edgar7777\spfuser]
FROM WINDOWS WITH DEFAULT_DATABASE = college,
DEFAULT_LANGUAGE = us_english;

Результат: Ошибка Msg 15401 — пользователь или группа Windows NT не найдены.

### Анализ
Ошибка возникла из-за отсутствия Windows-учётки [Edgar7777\spfuser] на сервере. SQL Server не может создать логин для несуществующего пользователя Windows.

### Вывод
Для создания Windows-логина нужно, чтобы учётка существовала в системе. Иначе Msg 15401.

## Слайд 15. Создание логина через sp_addlogin

### Что требовалось
Создать логин через устаревшую процедуру sp_addlogin.

### Что сделано

EXEC sp_addlogin
    @loginame   = 'spfuser',
    @passwd     = 'ВашНадёжныйПароль123!',
    @defdb      = 'College',
    @deflanguage = 'us_english';

Результат: Выполнение команд успешно завершено.

### Разбор sp_addlogin

| Параметр | Значение | Что означает |
|---|---|---|
| @loginame | spfuser | Имя логина |
| @passwd | ВашНадёжныйПароль123! | Пароль |
| @defdb | College | База по умолчанию |
| @deflanguage | us_english | Язык по умолчанию |

### Анализ
sp_addlogin — устаревшая процедура (SQL Server 2005+). Microsoft рекомендует CREATE LOGIN.

CREATE LOGIN spfuser
WITH PASSWORD = 'ВашНадёжныйПароль123!',
     DEFAULT_DATABASE = college,
     DEFAULT_LANGUAGE = us_english;

### Вывод
Оба способа дают одинаковый результат. Устаревшие sp_addlogin/sp_adduser использовать не рекомендуется.

## Слайд 15 (продолжение). Создание пользователя БД и роли через GUI

### Что требовалось
Показать создание пользователя БД и роли через графический интерфейс SSMS.

### Что сделано
Открыто окно «Пользователь базы данных — Создать» с разделами: Общие, Собственные схемы, Членство, Защищаемые объекты, Расширенные свойства.

В разделе Членство — список фиксированных ролей БД:

| Роль | Что даёт |
|---|---|
| db_accessadmin | Управление доступом |
| db_backupoperator | Резервное копирование |
| db_datareader | Чтение всех таблиц |
| db_datawriter | Запись во все таблицы |
| db_ddladmin | Изменение структуры (DDL) |
| db_denydatareader | Запрет чтения |
| db_denydatawriter | Запрет записи |
| db_owner | Полные права |
| db_securityadmin | Управление ролями и правами |

Открыто окно «Роль базы данных — Создать»: имя роли, владелец, схемы, члены роли.

### Анализ
Фиксированные роли дают типовые наборы прав. Принцип минимальных привилегий — давать только нужные роли.

Эквивалент в T-SQL:

CREATE USER spfuser FOR LOGIN spfuser;
ALTER ROLE db_datareader ADD MEMBER spfuser;
CREATE ROLE CustomReaderRole;
GRANT SELECT ON dbo.STUDENT TO CustomReaderRole;

### Вывод
GUI SSMS удобен для разовых операций. Для автоматизации и версионирования лучше T-SQL.

5. GUI SSMS удобен для разовых операций, T-SQL — для автоматизации.
